# Power opportunity matrix

Status: consolidated from the seven lane reports in this directory. This file is
an evidence index, not a release gate and not a merge plan.

Scope rules:

- Camera parity work is out of scope. No row here changes camera protocol
  behavior, pairing parity, or vendor feature coverage.
- Every row keeps the evidence label its lane used. Labels are not re-graded in
  this file. `measured-local`, `measured-vendor`, `datasheet`, `vendor-doc`,
  `code`, `model`, `plan-estimate`, `modeled`, `inferred`, `unknown`, and
  `unverified` all appear with their lane meaning.
- A modeled or inferred saving is not a measurement. Only the bench plan in
  `measurement-plan.md` can promote one.
- Merged rows list every source ID. A row is counted once, under its primary
  lane. The per-lane totals therefore count consolidated rows, not raw lane IDs.

The measurement lane contributes no device opportunity rows. Its states,
thresholds, and promotion rules are in `measurement-plan.md`.

## How to read the columns

| Column | Meaning |
| --- | --- |
| ID | Coordinator ID. Stable in this file. |
| Lane | Primary lane. Merged rows name the other lanes in `Lane source`. |
| Current behavior | What the tree does today, as the lane read it. |
| Proposed change | The smallest change the lane proposed. |
| Evidence | The lane's own label, plus its basis when the lane gave one. |
| Est. saving | The lane's number and basis. Not a measurement. |
| Risk | The lane's risk. |
| Effort | The lane's effort. |
| Required test | The merge gate the lane named. |
| Priority | Rank within the rank group. 1 is first. `-` for rejected. |
| Lane source | Lane-local IDs and the lane file. |

Rank groups:

- **Safe now**: the mechanism is understood and the direction is safe without a
  new hardware current measurement. Each row still needs its test.
- **Needs measurement**: a default change, a model change, or a user-visible
  trade that requires bench evidence or a product decision first.
- **Rejected**: no action on current evidence, or a change that would weaken
  correctness or security.

## Notes on scope and evidence

Non-additivity:

- P-084, P-085, and P-086 are alternative receiver policies. They act on the
  same receiver current and must not be summed. P-084 backs off when there is no
  fix, P-085 backs off when the device is stationary, and P-086 redesigns the
  scheduled duty window.
- P-040, P-041, P-042, and P-043 are nested connection policies. P-042 changes
  the fast floor, P-041 adds the idle profile, P-043 extends the idle profile,
  and P-040 allows light sleep while connected. Their savings overlap.
- P-001, P-002, P-048, and P-050 interact. P-050 changes the base discovery
  preset, P-048 adds a decay from Full, P-002 stops the scan when the panel
  sleeps, and P-001 bounds the page in time.
- P-071 and P-072 are per-board alternatives for the same APB lock. They are not
  additive across boards.
- P-073 and P-076 are sequential. P-073 turns the panel off; P-076 turns the
  device off after a longer idle period.
- P-065, P-066, and P-067 are three different deep-sleep implementations. Do not
  average or add them.

Other notes:

- P-040 and P-041 are the two rows that most other battery-life claims depend
  on. They are also the two rows whose anchor measurement is disputed (X-01).
- P-071 and P-072 are the only rows that can cut the MCU term while the screen
  is on. Both are in the flicker and panel-corruption risk class, and both need
  the APB-lock test before a default.
- P-065, P-066, and P-067 are three different deep-sleep implementations with
  three different risk profiles. Do not average them.
- P-056, P-057, and P-058 are model corrections, not device savings. They are
  prerequisites for trusting any ranking that uses the simulator.
- The Wi-Fi rows are mostly mechanism-first because the model has no Wi-Fi term
  and the simulator has a stub `FurbleWiFi`. No Wi-Fi row can be CI-gated until
  that changes.
- No row in this file is a bench measurement. The only `measured` values quoted
  are earlier project observations or vendor publications, and each row names
  its source.
- Camera parity is not represented here. The camera rows in the bench plan are
  power measurements of link states, not parity claims.
