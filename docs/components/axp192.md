# X-Powers AXP192

**Part and package.** X-Powers AXP192, a single-cell Li-battery PMIC with a
16-channel 12-bit ADC bank, a charger and four output regulators. Package and
pinout were not read and are UNVERIFIED.

**Role in furble.** The PMIC on the M5Stack Core2 and the StickC family. The
pinned board support library drives it, so furble only writes two registers
directly: the ADC enable pair, to switch off the channels M5Unified turns on and
never reads.

**Status.** board support. M5Unified's `Power_Class` owns the bus traffic on
`m5stick-c`, `m5stick-c-plus` and `m5stack-core2`, and a M5Tough runs the Core2
image on the same part. furble holds no register table of its own beyond the two
ADC enable writes.

**Documents.** [AXP192-CN], [AXP192-EN], [AXP192-CHIPBAY]

Row 9 and row 10 are separate because the document separates them, and the
earlier single row conflated them. The 100 uA is IQ, the current the LDO block
draws for itself. It is not a rail load and it is not a system current. The
off-mode and suspend figures are whole-chip measurements at BAT 3.8 V. The
power model at `tools/power-model/board-currents.yaml:293` sums the block
quiescent currents, DCDC1 26 uA, DCDC3 20 uA and the two 100 uA LDO figures, to
bound the operating floor, which is what those rows can support. Its note that
the datasheet gives no whole-chip operating figure is correct.

## Two consequences plan 385 recorded without changing the code

- Writing `0x83` = 0x00 clears bit 7, the internal temperature channel.
  `AXP192_Class::getInternalTemperature()` reads that conversion from REG 5EH
  (M5Unified 0.2.20, `AXP192_Class.cpp` lines 302 to 305), so a future furble
  consumer of the call has to re-enable the bit first. No furble code reads
  temperature today, which is why the trim stands: the channel is 25 Hz of ADC
  conversions nothing consumes.
- The vendored library computes the battery voltage from the four bytes at
  `0x78` as `(buf[0] << 4) + buf[1]` (`AXP192_Class.cpp` lines 196 to 200). The
  AXP192 puts the low four bits of that conversion in bits 7:4 of `0x79`, so the
  vendor arithmetic does not shift the second byte. That is a defect in
  M5Unified, not in furble, and it is recorded here because every AXP192 board's
  battery percentage comes through that call. It is UNVERIFIED on a device: see
  U-11 of plan 385, which needs a meter comparison at two pack voltages.

## Where the code implements it

- `src/FurblePlatform.cpp:185-188`: the ADC trim, guarded so it only runs when
  the detected PMIC really is an AXP192.
- `include/FurblePlatformPolicy.h:26-60`: the channel map, the two enable values
  and the helper that checks a mask keeps the four channels furble reads.
- `src/FurbleBoard.cpp:18` to `:23`: the rail notes that name EXTEN.
- `src/FurbleBoard.cpp:31` to `:52`: the click-streak flag per board.
