# NXP PCF8563

**Part and package.** NXP PCF8563, a real-time clock and calendar with a
programmable clock output, an interrupt output and a voltage-low detector.
Package and pinout were not read and are UNVERIFIED.

**Role in furble.** The RTC on boards that have one. The board support library
owns the bus traffic, and furble reads the time and the voltage-low flag through
it. The flag decides how long a time sample may be trusted
(`src/FurbleTimeKeeper.cpp:131` to `:146`).

**Status.** board support. The part itself is not fitted on a supported board:
its register set is what the BM8563 on the Plus2 implements, and
`src/FurbleTimeKeeper.cpp` speaks it through M5Unified.

**Documents.** [PCF8563-DS]

## Where furble relies on the timer

The Plus2 has no PMIC timer, so its timed wake is an RTC alarm
(`src/FurbleBoard.cpp:38`, `include/FurbleBoard.h:17`). The chain is:

- `src/FurblePlatform.cpp:785` checks the board profile for
  `TimedWake::RTC_ALARM`.
- `src/FurblePlatform.cpp:794` calls `M5.Rtc.setAlarmIRQ(requested_seconds)`.
- M5Unified's `RTC_Class::setAlarmIRQ` divides by 1000 and calls
  `setTimerIRQ`, at `src/utility/RTC_Class.hpp:52`.
- M5Unified's `PCF8563_Class::setTimerIRQ` at `src/utility/rtc/PCF8563_Class.cpp:121`
  writes 0x0E = 0x82 for a request up to 270 s, or 0x83 above that, then writes
  the count to 0x0F and enables the timer through 0x01 bit 0.

The 0x82 and 0x83 values are the timer control field values, not register
addresses. That is why the register document matters: 0x82 means a 1 Hz tick and
0x83 means a 1/60 Hz tick, so the same count register means seconds in one case
and minutes in the other, and the return value at `PCF8563_Class.cpp:151`
multiplies by the division to report the real interval.

`src/FurblePlatform.cpp:715` and `:844` hold the wake-source configuration and
the post-wake check. The PCF8563 document is the source for the timer semantics.
It is cited nowhere in the plans or in `docs/power/datasheet-register.md`, which
this change also fixes.

## Where the code implements it

- `src/FurbleTimeKeeper.cpp:127` to `:146`: reads the time, checks the flag and
  sets the sample validity window.
- `src/FurbleTimeKeeper.cpp:261`: records whether the board profile claims a
  battery-backed RTC.
- `src/FurbleTimeKeeper.cpp:390`: falls back to an NVS checkpoint when the RTC
  is not battery backed.
