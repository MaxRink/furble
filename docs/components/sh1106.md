# Sino Wealth SH1106

**Part and package.** Sino Wealth SH1106, a 132 x 64 dot matrix OLED and PLED
segment and common driver with an on-chip controller. Package and pad layout
were not read and are UNVERIFIED.

**Role in furble.** Driven on the LilyGO T-Beam Supreme image, which carries a
1.3 inch 128 x 64 module on the board's I2C bus 0 at SDA 17 and SCL 18. The
panel is M5GFX's `lgfx::Panel_SH110x`, a `Panel_1bitOLED` with its own 1 KB
frame buffer, so furble configures the panel class instead of writing a driver
(`src/FurbleDisplay.cpp:149`, `src/FurbleDisplay.cpp:148`). The column offset
is the class's `setWindow()` business; the 2-column difference between
the 132-column RAM and the 128-pixel window is not a furble constant.

**Status.** simulator-tested, hardware-untested. The T-Beam image has not run on
a device. See [plan 367](../plans/367-tbeam-supreme-port.md).

**Documents.** No vendor copy is in the tree. Sino Wealth's SH1106 V2.3 is
described by two distributor mirrors of the same text; neither is committed.

## Where the code implements it

- `include/FurbleDisplay.h` is the seam the UI draws through. The M5 boards
  forward it to `M5.Display`; the T-Beam answers with its own device.
- `src/FurbleDisplay.cpp` owns the device, the address probe and the simulator
  model.
- `include/FurbleBoardCaps.h:109` turns the board macro into
  `FURBLE_PANEL_128X64`, and the same macro joins `FURBLE_PANEL_NARROW` at
  `include/FurbleBoardCaps.h:116` so the tier takes 24 px icons and the short
  unit labels.
- The UI's touch calibration is compiled out on this panel, because the module
  has no touch controller.

## Facts still unverified

- The measured column offset on a real module, and the two strap variants.
- The contrast floor that is usable outdoors, which is a bench brightness check
  rather than a register fact.
- The charge pump configuration and the power-on sequence, which
  `Panel_SH110x::init()` owns and furble does not override.
- Which board revision carries which address strap. The schematic note gives
  VHF as 0x3C and UHF as 0x3D, and plan 318 records that the mapping is not
  confirmed against a product listing.
- Everything about the panel's sleep current, which plan 322 records from the
  distributor copy of V2.3 as 5 mA maximum on both supply rows.
