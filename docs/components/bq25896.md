# Texas Instruments BQ25896

**Part and package.** TI BQ25896, an I2C controlled single-cell switch-mode
charger with power path and OTG boost. Package and pinout were not read and are
UNVERIFIED.

**Role in furble.** None yet. The T-LoRa Pager carries it, and the plan records
why no driver exists: the BQ27220 current sign already tells furble whether the
pack is charging or discharging, so the charger is left to its power-on defaults
(`plans/322-hardware-abstraction.md`, phase 1 audit, BQ25896 row).

**Documents.** [BQ25896-DS]

## Facts furble depends on

| # | Fact | Document and section | Code | State |
| :--- | :--- | :--- | :--- | :--- |
| 1 | The I2C slave address is 6BH, given as 1101011B plus the read/write bit | BQ25896-DS section 9.4 Register Maps, page 32 | none | VERIFIED |
| 2 | REG00 bits 5:0 are IINLIM, an input current limit with a 100 mA offset and a 50 mA step, from 100 mA at 000000 to 3.25 A at 111111, default 0001000 for 500 mA. The effective limit is the lower of I2C and the ILIM pin | BQ25896-DS section 9.4.1 REG00, page 32 | none | VERIFIED |
| 3 | REG05 bits 7:4 are IPRECHG with a 64 mA offset, range 64 mA to 1024 mA, default 0001 for 128 mA. Bits 3:0 are ITERM with the same offset and range, default 0011 for 256 mA | BQ25896-DS section 9.4.6 REG05, page 37 | none | VERIFIED |
| 4 | REG07 bits 5:4 are the I2C watchdog timer: 00 disabled, 01 for 40 s and the default, 10 for 80 s, 11 for 160 s | BQ25896-DS section 9.4.8 REG07, page 39 | none | VERIFIED |
| 5 | REG0B bits 4:3 are CHRG_STAT: 00 not charging, 01 pre-charge, 10 fast charging, 11 charge termination done | BQ25896-DS section 9.4.12 REG0B, page 43 | none | VERIFIED |
| 6 | The bus runs at 400 kHz | BQ25896-DS section 8.6 Timing Requirements, I2C INTERFACE table, page 12 | none | VERIFIED |
| 7 | The charger is not configured by furble, so it runs in default mode: an autonomous charger with no host management, starting after power-on-reset with every register at its default value | `plans/322-hardware-abstraction.md` | none | VERIFIED |
| 8 | Any register write moves the charger from default mode to host mode. To stay there the host must rewrite the watchdog or set the WATCHDOG bits to 00. When the watchdog expires the part returns to default mode and every register reloads its default value except IINLIM, VINDPM, VINDPM_OS, BATFET_RST_EN, BATFET_DLY and BATFET_DIS | BQ25896-DS section 9.3.1 Host Mode and Default Mode, page 31 | none | VERIFIED |

Row 7 and row 8 together are the reason rows 2 to 4 matter and the reason a
future driver has to be deliberate. The part is designed to charge on its own
with no host, so leaving it alone is a supported mode, not an omission. Reading
it is the part that needs care: the first write puts it in host mode, and if the
host then stops writing the watchdog expires 40 s later and rewrites every
register except the six section 9.3.1 lists. Note that IINLIM is one of the
exceptions, so a host that set an input limit keeps it across the expiry, while
an IPRECHG or ITERM change does not survive.
