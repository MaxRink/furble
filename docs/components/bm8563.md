# Belling BM8563

**Part and package.** Belling BM8563, a real-time clock and calendar in the
PCF8563 family, 16 eight-bit registers, SOP8, MSOP8 or TSSOP8. Package and
pinout were not read and are UNVERIFIED.

**Status.** shipped. `m5stick-c-plus2` uses it for the timed wake, and the
StickC family shares its interrupt on the SYS_INT net with the MPU-6886.

**Role in furble.** The RTC on the StickC Plus2, where it shares the GPIO35
interrupt line with the MPU6886 (`src/FurbleBoard.cpp:21-27`). furble reads the time
through the board support library and treats the RTC as battery backed only when
the board profile says so (`src/FurbleTimeKeeper.cpp:261`).

**Documents.** [BM8563-CN]

The AE polarity in row 7 is the one that catches people out. It is the inverse
of every other enable bit on this page. A driver that sets AE to arm an alarm
gets a silent alarm that never fires. Section 2 says the same thing in prose:
when the MSB of one or more alarm registers is cleared to 0, the corresponding
alarm condition becomes active.

## Two vendor inconsistencies

| Inconsistency | Where | What this corpus read |
| :--- | :--- | :--- |
| The feature list gives the operating range as 1.5 to 5.5 V, while both electrical tables are written for a narrower supply | BM8563-CN section 1 page 1 against section 3 page 3 and section 4 page 4 | The feature list says 宽工作电压范围：1.5～5.5V. The DC and AC characteristics are both headed "VDD=1.8～5.5V". The DC table does carry one 1.5 V row, the I2C bus inactive case at TA=25 C, and the I2C bus active case is 1.8 V. So 1.5 V is a storage-adjacent condition, not the tested supply range. |
| A 2021 Belling catalogue is reported to quote 550 nA at 5.0 V where the datasheet quotes 0.25 uA at 3.0 V | Reported by the verification pass. This corpus did not open the catalogue. | Both figures are in the datasheet's own DC table on page 3. It is one row, IDD1, CLKOUT enabled, fSCL 0 Hz, TA 25 C: 550 nA typical and 800 nA maximum at VDD=5.0 V, then 250 nA typical and 650 nA maximum at VDD=3.0 V. The feature list quotes the 3.0 V figure as 0.25 uA and matches. The two numbers are the same parameter at two supplies, so they do not contradict each other, and a catalogue quoting 550 nA without its 5.0 V condition is incomplete rather than wrong. |

The second row is recorded as a correction to the pass rather than as a vendor
defect. The datasheet is internally consistent on the sleep current, and this
page would be repeating a false claim if it said otherwise.

One more vendor defect, seen on the cover: the part number printed under the
title is `MAX1937`, which is not this part.

The three values the firmware writes are exactly the table 22 encodings, which is
what makes the readback comparison below meaningful.

## Timer arithmetic

M5Unified's `setTimerIRQ()` returns the duration its own arithmetic selected even
when the underlying register writes fail, so the value alone is not evidence that
the timer was armed. The firmware therefore reads the three registers back and
compares them against the value it expects (`src/FurblePlatform.cpp:39-41,62-79`).

| Rule | Value | Citation |
| :--- | :--- | :--- |
| Minute mode threshold | requested seconds at or above 270 | `src/FurblePlatform.cpp:55` |
| Second resolution | below 270 s, divisor 1 | `src/FurblePlatform.cpp:56` |
| Minute resolution | at or above 270 s, rounded with +30 then divided by 60 | `src/FurblePlatform.cpp:56-57` |
| Count saturation | 255, which is about 255 minutes | `src/FurblePlatform.cpp:60,784-786` |
| Expected control byte | 0x83 in minute mode, 0x82 in second mode | `src/FurblePlatform.cpp:62` |
| First tick loss | a count one lower than expected still counts as armed | `src/FurblePlatform.cpp:71-74` |
| Maximum early wake | 60 s, or the resume validation clears the run | `include/FurblePlatform.h:207`, `src/FurblePlatform.cpp:784-790` |

A late wake would miss the saved shot deadline, so anything above the request is
rejected. An early wake is only safe inside the 60 s resume window, because the
255-minute clamp can otherwise wake hours early (`src/FurblePlatform.cpp:780-790`).

## Failure handling

- If the RTC is not enabled the firmware logs that it is staying awake and
  returns false (`src/FurblePlatform.cpp:775-778`).
- A failed verification clears the countdown, disables the IRQ and returns false,
  so a half-armed timer cannot wake the device after a manual power off
  (`src/FurblePlatform.cpp:50-53,791-796`).

## Shared interrupt net

On the StickC family the BM8563 and the MPU6886 share GPIO 35 as SYS_INT, and
M5Unified configures that pin open drain, so an external pull-up is required
(`src/FurbleBoard.cpp:21-27`, `src/FurbleIMUMotionMPU6886.cpp:54-57`).
