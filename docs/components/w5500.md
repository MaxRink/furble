# WIZnet W5500

**Part and package.** WIZnet W5500, a hardwired TCP/IP Ethernet controller with an
SPI host interface. Package and pinout were not read and are UNVERIFIED.

**Status.** shipped. `waveshare-s3-eth` is the only board with the part, and
`src/FurbleEthernet.cpp` owns the SPI bus and the reset line.

**Role in furble.** The Ethernet interface on the Waveshare ESP32-S3-ETH board.
furble sets up the SPI bus and hands the chip to the network stack, so it owns the
bus configuration and nothing below it (`src/FurbleEthernet.cpp:128` to `:170`).

**Documents.** [W5500-DS]

## Code defect: the reset pulse is too short

- `src/FurbleEthernet.cpp:192` passes only `phyConfig.reset_gpio_num`. The pulse
  width belongs to the pinned stack.
- ESP-IDF 5.5.3, `components/esp_eth/src/spi/w5500/esp_eth_phy_w5500.c:152` to
  `:163`, function `w5500_reset_hw`, holds the pin low for
  `esp_rom_delay_us(100)` at line 160 with the comment "insert min input assert
  time". That is 100 us against the 500 us minimum.
- The package is pinned as `framework-espidf@3.50503.0` in `platformio.ini:13`,
  and its `version.txt` reads 5.5.3. The line numbers above were read in that
  installed package.
- The defect is latent unless the board needs the full reset window: a short
  pulse usually resets the part, but a marginal supply or a slow oscillator can
  leave it unreset. furble has no way to lengthen the pulse without owning the
  reset GPIO itself.
- The host boundary double asserts only the pin number,
  `tests/host/boundaries/ethernet_w5500_test.cpp:183`
  (`config->reset_gpio_num == 9`), so no host test can catch the short pulse.
  The fix and the test both need a firmware change, which this change does not
  make.

## Initialisation order

1. Install the GPIO ISR service. `ESP_ERR_INVALID_STATE` counts as success
   because the service is process-global and may already exist
   (`src/FurbleEthernet.cpp:158-166`).
2. `spi_bus_initialize(SPI2_HOST, ..., SPI_DMA_CH_AUTO)`
   (`src/FurbleEthernet.cpp:165`).
3. Add the SPI device with a queue depth of 20 and mode 0
   (`src/FurbleEthernet.cpp:171-179`).
4. Create the W5500 MAC, then the PHY with the reset pin
   (`src/FurbleEthernet.cpp:180-196`).
5. Create the netif glue, register the link and IP event handlers, and use the
   default event loop (`src/FurbleEthernet.cpp:227,240-257,415`).

## State model

The transport reports `LINK_UP`, `LINK_DOWN`, `GOT_IP` and `IP_LOST`
(`src/FurbleEthernet.cpp:37-72`). The network-up callback fires only on the first
connection or on an IP change, so a repeated `GOT_IP` with the same address does
not re-run the consumer's setup (`src/FurbleEthernet.cpp:58-68`).

Two mutexes exist on purpose. `g_StateMutex` guards the published state and is
never held across a callback, and `g_LifecycleMutex` serialises `init()`,
`start()` and `stop()` because a transport may emit callbacks synchronously
(`src/FurbleEthernet.cpp:22-30`).

A lifecycle epoch is captured with every event, and an event whose epoch does not
match is dropped, so a callback from a stopped transport cannot resurrect state
(`src/FurbleEthernet.cpp:33,37-43`).

## Error handling

Every ESP-IDF failure path logs the call name and the error code and returns
false (`src/FurbleEthernet.cpp:159-196`). A failed MAC or PHY creation calls
`stop()` before returning, which frees the SPI bus the init acquired
(`src/FurbleEthernet.cpp:186-195,329`).

The display-less image has no battery and no PMIC, so `status` reports battery
level and voltage as unknown and current as unavailable rather than inferring USB
or PoE power from the link
([console commands](../console-commands.md#ui-workflow-commands)).
