# Texas Instruments BQ27220

**Part and package.** TI BQ27220, a single-cell CEDV fuel gauge with an I2C
interface. The driver does not depend on the package; the datasheet front
matter names a 9-ball WCSP and a 12-pin WSON variant, and the exact package of
a given board is UNVERIFIED for this page.

**Role in furble.** Reads voltage, current, state of charge, time to empty and
the battery status word so a board with a gauge reports real battery figures.
Read-only: the driver never unseals the gauge and never touches data memory
(`lib/hal/BQ27220.h:6` to `:16`).

**Documents.** [BQ27220-TRM]

## Where the code implements it

- `lib/hal/BQ27220.cpp:23` `word()`: reads two bytes at the command code and
  assembles them low byte first.
- `lib/hal/BQ27220.cpp:32` `read()`: five commands, any failure fails the whole
  reading, percent capped at 100, status bits split into `present` and
  `discharging`.
- `tests/host/hal_drivers_test.cpp`: expected command bytes and status bits are
  stated from the manual, not from the driver constants.

## Facts still unverified

- The bit positions of BATTPRES and DSG in Table 2-6, and their polarity.
- The 0x55 7-bit address and section 5.1.
- The 0xFFFF sentinel for TimeToEmpty().
- The CEDV profile behaviour and any need for a battery profile load: the driver
  deliberately avoids data memory, so a gauge with no profile reports what its
  firmware holds, and furble does not check that.
- Package variants and pinout.

## Hardware constraints

The command pacing in the technical reference manual is a bus timing
constraint, not a register, and the driver does not implement it.

| Constraint | Document and section | Where it bites | State |
| :--- | :--- | :--- | :--- |
| At least 66 us of bus-free time between packets, and no more than two standard commands per second, or the gauge watchdog can reset the part | BQ27220-TRM section 5.3 and page 64 | `lib/hal/BQ27220.cpp:32` to `:48` | REPORTED |
| `read()` issues five standard commands back to back: Voltage 0x08, BatteryStatus 0x0A, Current 0x0C, TimeToEmpty 0x16, StateOfCharge 0x2C | Same pacing limit, read against the driver | `lib/hal/BQ27220.cpp:38` to `:43` (command list read in the driver) | REPORTED |
| The bus seam has no delay hook, so a caller cannot insert the gap without a new seam | Read against the driver | `lib/hal/HalBus.h:32` to `:42` (`read8`, `write8`, `update8` only) (code fact, no document claim) | UNVERIFIED |

The driver is unconnected. No file under `src/`, `include/` or `components/`
includes `BQ27220.h` at this commit, so the five-command burst cannot happen on
a board today. The risk is latent: the first board that wires the driver must
pace the reads, or the seam must gain a delay, or the gauge watchdog may reset
the part mid-read.
