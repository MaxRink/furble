# Bosch BMI270

**Part and package.** Bosch Sensortec BMI270, a six-axis inertial measurement unit
with an integrated feature engine. Package and pinout were not read and are
UNVERIFIED.

**Role in furble.** The IMU and any-motion source on the StickS3. furble uses the
feature engine for any-motion and no-motion instead of polling, so the IMU stays
in a low power state between events (`src/FurbleIMUMotionBMI270.cpp:17` to `:80`).

**Documents.** [BMI270-DS], [BMI270-API]

Row 8 replaces a claim this page used to make. It said the any-motion and
no-motion feature layout was described only by the SensorAPI and not by the
datasheet. That was false. Section 5.2.40 devotes pages 88 to 93 to the FEATURES
register block, and the any-motion page inside it, page 92, prints both registers
with their bit fields, ranges and defaults. The SensorAPI is a convenience, not
the only source, and the corpus no longer says otherwise.

The threshold scale is arithmetic on two datasheet values. The datasheet gives
the range as 0 to 1 g over 11 bits and the default as 0xAA = 83 mg. 0xAA is 170
counts, so 83 mg over 170 counts is 0.488 mg per count. The datasheet does not
print a mg per LSB figure, so this is a derivation and the page labels it as one
rather than as a quoted specification.

The verification passes read revision 1.6 and found ten errors in the numbers
the page carried: nine section numbers and one register address, all inherited
from the source comments. Every corrected section was reopened for this change
and every one is now VERIFIED, with its page.

PWR_CTRL was the last open section number, and 5.2.85 on page 120 closes it.

The comments for INT_STATUS_0, INTERNAL_STATUS, FEAT_PAGE, FEATURES,
INT1_MAP_FEAT and INT_MAP_DATA are corrected in the corpus branch. Four source
comments are still open: `src/FurbleIMUMotionBMI270.cpp:39`, `:45` and `:62`
carry the old numbers, and `:72` names section 5.2.45 for PWR_CTRL, which is now
known to be 5.2.85. The file header at `:17` to `:21` also still says the
any-motion and no-motion layout is not in the datasheet, which row 8 above
disproves. Correcting those is a firmware comment change and is left to the
follow-up in plan 333.
