# CASIC AT6668

**Part and package.** CASIC AT6668, a GNSS receiver with GPS, BeiDou and other
constellations, in the M5Stack Unit GPS and in the GPS unit v1.1 that furble
uses. Package and pinout were not read and are UNVERIFIED.

**Role in furble.** The GNSS receiver behind the GPS feature. furble talks to it
over UART with NMEA and the CASIC `$PCAS` command family, and falls back to those
commands when the attached receiver is not a u-blox M10
(`src/FurbleGPS.cpp:610`, `:737`).

**Documents.** [DS-AT6668]

## Where the code implements it

- `lib/furble/protocol/GpsCasic.cpp:11` to `:16`: the frame overhead and sync
  bytes.
- `src/FurbleGPS.cpp:1279`: `$PCAS10` mode selection.
- `src/FurbleGPS.cpp:765`: `$PCAS12` timed standby.
- `src/FurbleConsole.cpp:1297`: the console path that writes a sentence straight
  to the GPS UART.
- `src/FurbleGPSUbx.cpp`: the u-blox path that runs when the receiver answers
  UBX instead of CASIC.

## Facts still unverified

Every fact above except 7. DS-AT6668 V1.4 supplies the current, and this corpus
did not reopen it. The command names, their arguments and their limits still
come from the firmware and from the hardware traps in `CLAUDE.md`, because the
datasheet is not the authority for the command set.

Specifically unverified:

- The `$PCAS02`, `$PCAS03`, `$PCAS10` and `$PCAS12` argument ranges.
- The 108 s cold start.
- The absence of a backup supply on the module.
- The baud rate and the default sentence set.
- The in-circuit standby current for `$PCAS12`, which a chip datasheet cannot
  give because the rails and the regulator are board level.
