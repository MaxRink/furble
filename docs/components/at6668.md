# CASIC AT6668

**Part and package.** CASIC AT6668, a GNSS receiver SOC with BDS, GPS, GLONASS,
Galileo, QZSS and SBAS support. QFN40, 5 x 5 x 0.75 mm, 40 pins plus an exposed
pad that must be grounded (datasheet DS-AT6668 V1.4 section 1.5 page 1 and
sections 2.1 and 2.2 pages 3 to 4). The variant table in section 1.6 page 2
decides which signals a given part has, and it is the first thing to check
before trusting any constellation behaviour: AT6668-6N-22 is single-constellation
BDS, because footnote 1 says the 6N-22 supports no system other than BeiDou;
-6N-32 adds GPS/QZSS L1; -6N-74 adds Galileo E1 and GLONASS R1; and
AT6668U-6N-74 is the same signal set as -6N-74 with AEC-Q100 qualification and a
105 C ceiling where the others stop at 85 C. The unit furble drives carries the
all-system part, since the module manual gives it BDS, GPS/QZSS/SBAS, Galileo
and GLONASS (ATGM336H-6N V1.1 section 1.1 page 2 and section 2.6 page 11).

The unit furble drives carries the chip inside an ATGM336H-6N module, whose
manual gives the module as 10.1 x 9.7 mm and the chip as "中科微第六代多系统
GNSS SOC 单芯片 AT6668" (ATGM336H-6N 模块用户手册 V1.1 section 1.1 page 2 and
page 9, the module pinout).

**Status.** shipped. Every board with a Grove GPS unit uses it: the GPS path is
built into the image and the receiver is autodetected.

**Role in furble.** The GNSS receiver behind the GPS feature on the M5Stack
Unit GPS v1.1. furble talks to it over UART with NMEA and the CASIC `$PCAS`
command family, and falls back to those commands when the attached receiver is
not a u-blox M10 (`src/FurbleGPS.cpp:610`, `:737`).

**Documents.** [DS-AT6668], [DS-AT6668-V1.0], [CASIC-R6], [CASIC-V4.2.0.3],
[ATGM336H-6N], [UNIT-GPS-V1.1]

### The cold start conflict

The datasheet specifies cold start TTFF of 23 s or better, and the bench
observation on this hardware is about 108 s with no backup supply fitted
(`AT6668-DS` section 1.3, page 1, against `CLAUDE.md`). Both stay on the page.
The gap is either the antenna, the assist data, or the missing backup rail, and
none of those is settled by a document this branch can read. Do not delete the
observation because the datasheet is optimistic, and do not overwrite the
datasheet with the observation.

### The constellation ceiling

`CONSTELLATION_MAX` is 7 (`include/FurbleGPS.h:394`), so the firmware can send
`$PCAS04` values 1 to 7 and nothing else. Under both revisions those values cover
GPS, BDS and GLONASS and never reach Galileo E1, BDS B1C, QZSS or SBAS, which the
part supports and which the protocol encodes as bits 3 to 7 alone or combined
with those three. The firmware also never sends the `mode2` and `mode5`
arguments, so no dual-frequency constellation set is reachable. Nothing is wrong
with the values the code sends; the ceiling is a feature limit, and this page
records it rather than changing it.

## What the driver does with the stream

- A pure demultiplexer splits NMEA text, CASIC frames and UBX frames that share
  one UART, and resynchronises one byte at a time so a real frame hidden behind a
  false sync is still found (`lib/furble/protocol/GpsDemux.h:8-19`).
- GSV and GSA are parsed directly because the pinned TinyGPS++ fork parses only
  GGA and RMC. The parser reassembles multi-sentence GSV sets and keeps up to 32
  satellites in view and 64 used satellites
  (`lib/furble/protocol/GpsCasic.h:90-96,122-123`).
- The autobaud ladder runs 115200, 9600, 38400, 57600, 19200 and 4800 at 1200 ms
  per step and needs two checksum-passing sentences in one step
  (`lib/furble/protocol/GpsCasic.h:48-56`). After a failed ladder the receiver is
  marked absent, the rail is cut and one retry is scheduled 60 s later
  (`src/FurbleGPS.cpp:129-134,588-596`).
- The ephemeris cache stores up to 4096 bytes of verbatim assistance frames and
  replays them at a 30 ms gap (`lib/furble/protocol/GpsCasic.h:196-199`,
  `src/FurbleGPS.cpp:600-604`).

## Error handling

- A binary configuration frame waits for its acknowledgement with a bounded
  timeout (`src/FurbleGPS.cpp:607-612`), then falls back to the `$PCAS`
  sentence, and the fallback is recorded per field so the console can show
  `FALLBACK` (`src/FurbleGPS.cpp:1364-1369`).
- Every write is followed by `uart_wait_tx_done` with `TX_MS`, so a stuck UART
  cannot block the task forever (`src/FurbleGPS.cpp:1169-1181`).
- A short or malformed MON-HW payload returns `valid = false` rather than
  decoded garbage (`lib/furble/protocol/GpsCasic.h:242-243`).

- `src/FurbleGPS.cpp:1632` and `:1642`: the `$PCAS04` and `$PCAS11` fallbacks

- `src/FurbleGPS.cpp:3083` to `:3107` `GPS::setSatelliteCapture()`: the

  to the GPS UART.
- `src/FurbleGPSUbx.cpp`: the u-blox path that runs when the receiver answers

  VBAT input as 1.5, 3.0 and 3.6 V at 10 uA. Unit GPS v1.1 page 3 lists no
  backup supply and its pinmap on page 4 exposes only 5 V, GND and the two UART
  lines. M5Stack publishes a 23 s cold start, the datasheet and the module
  manual repeat it, and this project measured 107.7 s to re-fix after a 60 s
  rail cut (`plans/00-hardware-experiments.md` line 188, recorded as
  `cold_start_refix_s` in `tools/power-model/board-currents.yaml`). The two are
  not the same quantity and should not be quoted as if one contradicted the
  other: 23 s is the vendor's cold start TTFF specification, 107.7 s is this
  unit's re-fix in its own sky after the rail was cut. Nothing was measured on
  VBAT itself, and the unit schematic was not opened.
- **Which protocol revision the ROM in the unit implements.** R6 of 2025 and
  V4.2.0.3 of 2020 disagree about `$PCAS04`, `$PCAS15`, the binary classes and
  the `antStatus` encoding. The AT6668 datasheet of 2023 documents none of that,
  and no surface visible over the UART states a protocol revision. The
  `$PCAS04` and `$PCAS03` commands furble sends work on both, which is not the
  same as being correct on both.
- **A factory default baud rate.** DS-AT6668 documents no default. Unit GPS v1.1
  page 3 says 115200 8N1, which is what the autobaud ladder starts at, and
  `$PCAS01` in R6 section 2.7.2 page 34 selects 4800 to 460800. The 9600 the
  `lib/furble/protocol/GpsCasic.h` comment calls the CASIC factory default is
  not stated in either protocol revision.
- **The default sentence set.** R6 section 2.7.4 page 36 lists `$PCAS03` and
  `$PCAS07` but never says which sentences are on at power-up, and the unit
  documents only NMEA0183 4.1.
- **In-circuit standby current for `$PCAS12`.** DS-AT6668 section 4.3 page 9
  gives the chip in sleep at 30 uA with ON_OFF low, which is the pin the module
  exposes as ON/OFF and `$PCAS12` does not drive. The model keeps its estimate.
- **The 250 ms `$PCAS02` step.** Only V4.2.0.3 documents it. Whether an R6
  receiver accepts it is untested, and `RATE_MS` does not offer it.

## Redistribution

No document here is committed and none may be. CASIC V4.2.0.3 prints 内部文档
(internal document) in the header of every body page, which is a refusal under
the rule in [README.md](README.md#committed-documents). DS-AT6668 V1.4 and the
ATGM336H-6N manual carry no licence statement at all, and silence is not a
grant. The R6 copy is a M5Stack mirror of a CASIC document, and a mirror is
never committed even when the licence would allow it. The V1.4 datasheet is
cited from a distributor mirror because no vendor-domain copy exists; the only
vendor-domain copy found is V1.0.
