# Layout audit for the physical-button layout the M5Stack Core Basic ships, on the
# 320x240 panel.
#
# UI::begin() picks the navigation layout at runtime from M5.Touch.isEnabled().
# The Core Basic has no touch panel either, it has the three
# physical buttons A, B and C,
# so this is the layout it always renders: a navigation bar band reserved at the
# bottom of the window content, ICON_HEADER_SIZE + 2 = 26 px tall, plus the
# three button indicators. On the Core the three indicators live inside the bar
# rather than floating, so no indicator is ever drawn over page content and the
# clearance assertions below are all hard.
#
# The M5GFX SDL panel always attaches a mouse-driven touch device, so every
# other scenario measures the touch layout, which is 26 px taller. This one
# seeds "no_touch true" to detach that device. One file per board on purpose:
# the expectations below are geometry, and a shared file would have to soften
# every line to the weakest board.
#
# The first assertion is a hard guard. Without it a run that lost the seed would
# fall back to the touch layout and pass for the wrong reason, which is the
# exact failure this scenario exists to remove.
#
# Every xassert below is a WILL_FAIL that fails on this board today, with the
# measured pixel count or widget count in its comment. None of them is
# board-varies: each file covers one board, so a closed gap turns into an XPASS
# and fails the run, which is the signal to promote the line to a hard assert.
# See plans/165-sim-no-touch-layout.md.
seed no_touch true
seed fauxny true
seed saved_camera true
seed gps true
seed imu true
wait 300
assert ui.nav_layout buttons

# Home menu, six rows.
assert ui.page main
assert ui.overflow no
assert ui.indicator_clearance clear

# Display page.
action nav display
wait 150
assert ui.page display
assert ui.overflow no
assert ui.indicator_clearance clear

# Sensors tile.

assert ui.overflow no
assert ui.indicator_clearance clear
