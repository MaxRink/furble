# Reconnect after a user Disconnect, swept over the idle gap
#
# Bench, 2026-09-04, M5StickS3 on master with an X100VI, UI driven: after a
# manual Disconnect from an active session, Connect did not work again
# until furble was restarted. This walks the one variable the bench could
# not control, the time the user spent between the two presses, from the
# same tick through half a minute.
#
# Gaps: 0, 100, 500, 1000, 2000, 5000, 10000, 20000, 30000 ms.
#
# Each cycle asserts the session really came up, that the teardown settled
# (drain empty, no connect in flight, Control idle), and that the next
# connect comes back.
#
# This PASSES on master. That is a statement about the peer, not a clean
# bill of health for the firmware: the virtual camera goes on advertising
# the instant a central-initiated disconnect lands and holds no session
# state across it, so if the real X100VI needs seconds before it will
# accept a central again, or keeps the old session open, the simulator
# cannot see it yet. plans/172 records exactly what the bench capture has
# to show and what peer knob it turns into.
#
# The NimBLE client pool is capped at the board's CONFIG_BT_NIMBLE_MAX_CONNECTIONS
# (9) and the self-deleting client is modelled, so a client leaked per cycle
# ends this run instead of being invisible. Neither was modelled before plan 172:
# the mock pool was unlimited and a clean teardown never freed its client, so the
# simulator could not tell a leak from a healthy session at all.
seed ble_peers fuji-secure
seed ble_saved true
seed reconnect true
seed ble_max_clients 9
seed ble_client_selfdelete true
wait 300
assert control.state idle
assert_max ble.live_clients 1

# gap 0 ms between the Disconnect and the next Connect
action connect
assert-eventually-virtual 20000 control.state active
assert control.connected 1
action disconnect
assert-eventually-virtual 6000 control.zombies 0
assert control.connect_in_progress no
assert control.state idle
assert_max ble.live_clients 1

# gap 100 ms between the Disconnect and the next Connect
