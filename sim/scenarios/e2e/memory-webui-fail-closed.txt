# PR #392 fail-closed gate under the measured StickS3 internal-heap pressure.
#
# Hardware with WiFi, BLE, the companion service and the display active measured
# 13,543 free / 12,788 largest internal bytes with the WebUI off before the
# #394 RAM pass. The supervisor fits (4,608/4,096) but the HTTPS server does not
# (20,480/12,288), so the firmware logs the measured pair and stays closed.
# This scenario proves the same decision, the production log sentence, a bounded
# 10 s retry and a fed watchdog instead of the pre-#392 8 KiB/12 KiB allocation
# boot loop. The pair is an input, not a claim about the post-#394 image: seed
# the new measured pair here to re-check the gate after a RAM change.
seed heap_internal_free 13543
seed heap_internal_largest 12788
seed wifi_connected true
seed web_ui true
seed webui_password true
wait 100

assert heap.active yes
assert heap.free 9959
assert heap.largest 9204
assert webui.supervisor created
assert webui.server blocked
assert webui.gate server_memory
assert webui.fail_closed yes
assert heap.alloc_failures 0
print webui.gate_message
assert ui.page main
assert platform.watchdog armed

# 9,959 free is below the 12,288 AMBER floor, so after three readings the
# memory pressure governor (plan 314 PR 6) pauses the server: the one attempt
# at t=0 is the last, instead of a retry every 10 s. The bounded retry cadence
# above AMBER is memory-webui-retry-bounded.txt.
wait 25000
assert heap.pressure amber
assert_min webui.attempts 1
assert_max webui.attempts 1
assert heap.free 9959
assert heap.largest 9204
assert heap.alloc_failures 0
assert ui.page main
assert platform.watchdog armed

exit
