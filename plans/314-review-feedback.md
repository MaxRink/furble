# 314 - Review feedback for memory resilience

## Scope

This is the review-feedback record for plan 314. Each PR in the series adds a
section. Every Copilot or human finding is recorded as fixed, already fixed or
a false positive, with evidence.

## PR 1 (#411, `feat/314-sim-config-parity`)

| # | Finding | Resolution | Evidence |
| ---: | :--- | :--- | :--- |
| 1 | `heap_caps_aligned_alloc` applied the abort policy only to injected failures. A real host `posix_memalign` failure returned NULL into a fallback the device cannot reach. | Fixed. The host failure branch also calls `furble_sim_heap_alloc_failed()`, so it aborts under the board policy. | `sim/shim/esp_heap_caps.h` |
| 2 | The panic runner checked its tokens against the combined log of all fixtures, so one fixture could abort on the wrong allocation and borrow another fixture's tokens. | Fixed. `run_fixture` takes the expected abort line, task and record task, and checks them against that fixture's own run and record logs. A mutated expectation (`size 0x3004`) fails the icon fixture alone. The combined-log tokens remain as coverage evidence. | `sim/scripts/run-panic-fixtures.sh` |

| 3 | The panic recorder is registered from a namespace-scope dynamic initializer in `sim/CrashLogSim.cpp`, while the atomic it stores into lives in `sim/heap_model.cpp`; cross-unit initialization order is unspecified. | False positive, hardened. `std::atomic<T *>` has a constexpr constructor, so `s_PanicRecorder{nullptr}` is constant-initialized before any dynamic initializer runs ([basic.start.static]). Both hook atomics now carry `[[clang::require_constant_initialization]]`, so a change that made them dynamically initialized fails to compile. | `sim/heap_model.cpp` |

| 4 | Review body: the CMake configure step did not track `tools/gen_sim_sdkconfig.py`, so an allowlist change kept a stale `sdkconfig_sim.h` until a manual reconfigure. | Fixed. The generator is a `CMAKE_CONFIGURE_DEPENDS` entry next to the board sdkconfig. `sim/build.sh` already runs the generator on every build. | `sim/CMakeLists.txt` |
| 5 | Review body: enabling `CONFIG_SPIRAM` and `CONFIG_FREERTOS_TASK_CREATE_ALLOW_EXT_MEM` makes `src/FurbleIR.cpp` compile its `xTaskCreateWithCaps` path, which the simulator does not shim, so both simulator builds fail. | False positive. `src/FurbleIR.cpp` is not in the simulator source list of `sim/build.sh` or `sim/CMakeLists.txt`; the simulator uses `sim/shim/FurbleIR.h`. The linked boundary suite compiles the production IR file in `tests/host` without the generated header. Both simulator builds and the host suite build clean on this branch. | `sim/build.sh`, `sim/CMakeLists.txt`, `sim/shim/FurbleIR.h` |

Validation: `sh sim/scripts/run-panic-fixtures.sh` passes 3 of 3 after all
items; the CMake simulator configures and builds.

## PR 2 (#412, `feat/314-sim-count-allocations`)

| # | Finding | Resolution | Evidence |
| ---: | :--- | :--- | :--- |
| 1 | The `heap_caps_aligned_alloc`/`heap_caps_malloc` shim still used `posix_memalign` and `heap_caps_free` used `free`, so capability-placed device allocations bypassed the counter. | Fixed. The shim calls `furble_sim_caps_alloc()`/`furble_sim_caps_free()`. The simulator's counter charges the pool the caps name through `heapCountedAllocCaps()` and refunds it on free. Host unit targets keep plain weak fallbacks in `sim/heap_model.cpp`. | `sim/shim/esp_heap_caps.h`, `sim/heap_count.cpp`, `sim/heap_model.cpp` |
| 2 | The driver tick's host scope also covered `GPS_RESTART` and `GPS_MONHW`, which call straight into `GPS`. | Fixed. Both steps run in a `DeviceAllocScope`. The other GPS and UART steps drive the fake receiver or edit NVS from the harness and stay host work. | `sim/driver.cpp` |
| 3 | `fuzzTick` ran entirely in a device scope, so its event history, counters and findings were charged to the device heap. | Fixed. `fuzzTick` is a host scope; only `applyEvent()` and `escapeTick()`, the two firmware dispatch paths, re-enter device counting. | `sim/fuzz.cpp`, `sim/driver.cpp` |
| 4 | A task thread was marked as a device thread before `watchdogRegisterThread`, whose registry growth was then charged. | Fixed. Registration runs first. | `sim/freertos.cpp` |
| 5 | Task charges were `stack + 512` as one raw figure, without the per-block cost of the two `pvPortMalloc` blocks. | Fixed. A task is `blockBytes(stack) + blockBytes(336)`; 336 is `sizeof(StaticTask_t)` read from the m5stick-s3 ELF with the toolchain gdb. | `sim/heap_model.cpp` |
| 6 | Counted task stacks reduced `heap.free` but never entered `heap.counted_*`. | Fixed. `heapTaskCreate` reports whether the charge was counted, the task records it, and `heapReleaseTask` refunds the counted total. | `sim/heap_model.cpp`, `sim/freertos.cpp` |
| 7 | Self-found while bisecting the fixes above. The `sim/build.sh` cache stamp did not include per-file flags, so an existing build directory kept an `lv_mem_core_clib.c` object compiled before the counter defines and LVGL went uncounted. The first PR 2 figures were measured on such a build. | Fixed. The stamp carries a checksum of `sim/build.sh`, so any edit to the script drops the object cache. `sh sim/scripts/test-build-deps.sh` passes. Every PR 2 figure was re-measured on clean builds. | `sim/build.sh` |
| 8 | Self-found by the full fuzz corpus under counting. The StickC and Core simulators used the StickS3 LVGL image cache size, so seed 3 aborted the Core sim on an icon decode the device never caches. | Fixed. `sim/build.sh` and `sim/CMakeLists.txt` generate a per-build `lv_conf.h` with the board's `LV_CACHE_DEF_SIZE`. Font and DPI parity is recorded as PR 2c. | `sim/build.sh`, `sim/CMakeLists.txt` |
| 9 | Self-found. Counting from the first frame charged the one-second UI timers' first label and layout sizing (2,016 bytes on the StickS3), which the idle-device measurement already includes; the post-#407 budget read a false 2,391 / 1,044. | Fixed. Counting starts one UI timer period after the settled first frame, and baseline blocks freed later are refunded. The budget is back to its documented 4,407 / 3,060. | `sim/driver.cpp`, `sim/heap_count.cpp`, `sim/heap_model.cpp` |
| 10 | Review summary nit on f2fd2433: build output was checked in. | Fixed in a721b633. A wrapper loop had created `sim/build FURBLE_M5STICKS3 board_M5StickS3/`, which `git add -A` picked up; the directory is removed and diff hygiene passes. | `git ls-files sim/` |
| 11 | Review summary nit on f2fd2433: `fuzz_results.json` recorded `../hb-pr2/...` host fuzzer paths that cannot be replayed from the repository. | Fixed. Regenerated with the documented `FURBLE_HOST_BUILD=/tmp/furble-host-build`: 10 targets, 135 seed runs, 89,145 iterations, 0 failures. | `sim/coverage/fuzz_results.json` |

## PR 3 (#413, `feat/314-sim-board-baselines`)

| # | Finding | Resolution | Evidence |
| ---: | :--- | :--- | :--- |
| 1 | The boot terms omitted the static WiFi management RX pool (`CONFIG_ESP_WIFI_STATIC_RX_MGMT_BUFFER`, 5 buffers). | Fixed. `wifi_static_rx_mgmt` charges `CONFIG_ESP_WIFI_RX_MGMT_BUF_NUM_DEF` x 500 with block cost; the esp_wifi Kconfig help fixes each buffer at about 500 bytes. | `tools/derive_sim_heap.py` |
| 2 | The boot terms omitted board-conditional tasks from `app_main`: the IR task and queue, and the Core SD writer. | Fixed. StickC and StickC Plus charge the internal 4,096-byte IR task, the StickS3 only its internal queue (stack and TCB go to PSRAM through `xTaskCreateWithCaps`), and Core and Core2 charge the 6,144-byte SD writer and its 8 x 48-byte queue (`sizeof(message_t)` from DWARF). | `tools/derive_sim_heap.py`, `sim/coverage/board_heap.json` |
| 3 | The GPS boot cost charged only its 4,096-byte task, not the UART driver installed before it. | Fixed. `gps_uart_driver` charges what `uart_driver_install()` and `uart_pattern_queue_reset()` allocate in the pinned `uart.c`: `uart_obj_t`, the 128-word FIFO copy, the 32-event queue and 256-byte RX ring (control and storage blocks each), two mutexes, three binary semaphores and the 32-int pattern queue. Struct sizes are read from each ELF's DWARF. | `tools/derive_sim_heap.py` |
| 4 | `SD::init()` also creates `m_PowerOffDone`, a binary semaphore. | Fixed. Charged as a zero-item queue control block on Core and Core2. | `tools/derive_sim_heap.py` |

| 6 | Review summary, previously missed: the 32-entry Control queue created by `Control::getInstance()` in `app_main` was not charged. | Fixed, together with a sweep of every `xQueueCreate`, `xSemaphoreCreate` and `esp_timer_create` in `src/` and `lib/furble/` reached at boot. | `tools/derive_sim_heap.py` |
| 7 | Review summary, previously missed: the 8-slot UI request queue built by the display `UI` constructor was not charged. | Fixed. Charged on every display build. | 9 | Review summary: incorrect WiFi assumptions. | Fixed. WiFi starts only with the WiFi setting on and an SSID stored (`WiFi::init`). | 10 | Review summary: omitted event-loop costs. | Fixed. `esp_event_loop_create_default()` runs on every boot; the loop object, its 32 x 16-byte queue and its recursive mutex are charged (sizes from DWARF), and the tcpip task is charged unconditionally with `esp_netif_init()`. | `tools/derive_sim_heap.py` |
