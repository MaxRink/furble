# 321 review feedback

Two independent subagent reviews of the u-blox M10 stack. Both found the codec
and every configuration key ID correct against the SPG 5.10 interface
description (UBX-21035062 R03). The findings below were fixed as new commits
on `feat/ubx-3-features`; `feat/ubx-1-protocol` is unchanged. Every fix has a
regression that fails on the old code.

| # | Severity | Source | Finding | Resolution | Evidence |
| --- | --- | --- | --- | --- | --- |
| 1 | Critical | Subagent review | `m_ConfigNotBefore = 0` with `tickReached(now, 0)` reads as the future for every tick in [2^31, 2^32), so every configuration command, CASIC included, stalled between 24.8 and 49.7 days of uptime. `cycleWait` used the same value. | Fixed. `Ubx::Settle`, an explicitly armed one-shot gate, replaces the raw deadline in `startConfigCommand()` and `cycleWait()`. | `gps-ubx` `testSettle` (ticks around 2^31 and 2^32). `e2e/gps-ubx-tick-wrap` starts the clock past 2^31; with the old gate restored it fails at `gps.ubx.verified`. |
| 2 | Critical | Subagent review | The UPD-SOS save sends CFG-RST GNSS stop, but `setExtOutput(ext_PA)` does nothing on the Core (IP5306) and the Waveshare board, and the Core2 can refuse on low battery. The receiver stays powered and stopped, nothing restarts it, and Auto baud later marks it absent. | Fixed. New board capability `Platform::canCutGpsRail()`: true for StickC, StickC Plus, Core2 and StickS3; false for Core, Waveshare and headless; in the simulator, false on the Core build or with `seed gps_rail_fixed`. The save is skipped when it is false. `setRailPower()` now reports whether the rail reached the requested state. `railOffOrRestart()` sends CFG-RST GNSS start when the rail stayed on after a stop, in both `enterRailOff()` and `disable()`. | `e2e/gps-ubx-rail-fixed`: no CFG-RST and no UPD-SOS, and the receiver keeps fixing. The old code sends both. |
| 3 | Important | Subagent review | On the branch 2 tree the standby gate sent `$PCAS12` to any identified receiver. | Fixed. `$PCAS12` is sent only when the backend is NMEA, and RXM-PMREQ only when it is UBX. The final tree sends no `$PCAS12` to a UBX receiver. The plan 321 text, the code comment and `src/CLAUDE.md` now say so. | `e2e/gps-ubx-standby` asserts `uart.standby_5s_commands 0` and at least two PMREQs. |
| 4 | Important | Subagent review | A NAV-PVT with a valid position but a time that is not fully resolved dropped the whole fix, because date and time validity required `fullyResolved`. | Fixed. `date_valid` and `time_valid` come from `NavPvt::dateTimeValid()` (validDate and validTime). The new `status_t::time_resolved` is true on NMEA and `fullyResolved` on PVT, and gates `TimeKeeper::updateUtc`. A PVT sync passes `max(1000 ms, tAcc)` as the uncertainty. | `e2e/gps-ubx-time-unresolved` (valid 0x03, 3D fix): the fix reaches the camera and `time.gps` stays 0. `gps-ubx` checks `dateTimeValid`. |
| 5 | Important | Subagent review | `GPS_ANA` defaulted to true. Every other new setting leaves the receiver at its ROM default. | Fixed. Default false. The comment cites the computation cost (IM-MAX 3.12.5.3) and the BBR loss on unbacked boards. The settings docs, wiki, README and plan table are updated. The golden corpus was regenerated and does not encode the default, so it is unchanged. | `settings-nvs-roundtrip`, `e2e/gps-ubx-config` (`ana 0`), and `e2e/gps-ubx-ana` for the opt-in. |
| 6 | Important | Subagent review | The fuzzer's `clean` latch hid most delivery checks. The `processSerial` demultiplexer was not fuzzed. | Fixed. `gps_ubx_fuzz` now compares `Ubx::Stream` with a reference splitter built on `scan()`. It requires every intact frame to be yielded unless an unplaced checksum-valid frame was. It pads the stream so a trailing false sync cannot hold frames back. The demultiplexer moved to the pure `GpsDemux::split()` in `lib/furble/protocol`, which the firmware calls. It is fuzzed for contiguous pieces, valid frames, a bounded pending tail and chunking invariance. | 7 seeds x 5,000 iterations, 0 failures. `gps-ubx` `testDemux`. All 36 legacy GPS scenarios pass through the new demux. |
| 7 | Important | Subagent review | The CLAUDE.md files in touched directories missed the new contracts. | Fixed. `src/CLAUDE.md`: `disable()` can block for up to 1 s, `m_RailOffPending`, the refusal latch, RXM-PMREQ instead of `$PCAS12`, `Settle`, `GpsDemux`, the time-resolution gate. `sim/CLAUDE.md`: the seeds, the V_BCKP model, the warm-start assumption, the fixed rail. `lib/furble/CLAUDE.md` and `tests/host/CLAUDE.md`. | Doc review. `check-doc-tokens` passes. |
| 8 | Medium | Subagent review | Standby could collide with configuration on CASIC. | Fixed. The duty gate also waits for `!m_ConfigPending`, no command in flight and an empty queue. | Power gate within threshold. All GPS scenarios pass. |
| 9 | Medium | Subagent review | A stale PVT could overlay a newer NMEA fix. | Fixed. The PVT is skipped when the NMEA fix is more than 2 s (two epochs at 1 Hz) newer. | Code review. The UBX scenarios pass. |
| 10 | Medium | Subagent review | The ACK timing was cited as IFD 3.5.1. The "at least within one second" text is in 3.9.1 and 3.9.2. | Fixed in `GpsUbx.h`, `FurbleGPS.h` and plan 321. | Text diff. |
| 11 | Medium | Subagent review | `m_UbxSosBackup` was never reset. | Fixed. `resetUbx()` resets it, so the refusal latch lasts one GPS enable. Documented. | `e2e/gps-ubx-warm-start-sos` (one save per session). |
| 12 | Medium | Subagent review | `pollMonHw()` returned on UBX before clearing `m_MonHwHave`, so an old snapshot stayed visible. | Fixed. It now clears first. | Code review. |
| 13 | Medium | Subagent review | Docs: reverting `GPS_GNSS` or `GPS_PLATFORM` takes effect at the next receiver start; the `gps ubx` output on non-UBX receivers; the 10 s PSMOO period when `GPS_DUTY` is 0; SBAS in power save; `gps ubx` waking a standing-by receiver. | Fixed in the settings docs, the wiki and the console docs. SBAS is documented rather than forced off. | Doc diff. |
| 14 | Medium | Subagent review | Check the gps stack margin. The `getStatusSnapshot()` temporary on the late MON-VER answer path should not be on the deepest path. | Fixed. The late answer reads only `charsProcessed()` under `m_GPSMutex`. The margins measured on the final tree are recorded under the verification section of plan 321. | `stack_budget.py`. |
