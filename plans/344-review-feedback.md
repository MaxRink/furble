# 344 review feedback

A review of PR 483, the Robolectric UI snapshot test for the Android companion.
One blocking finding on the documented detection envelope and eight
non-blocking ones. All nine are fixed on `test/android-snapshot`. The pixel
counts below were remeasured with `./gradlew test` on the environment recorded
in [344-android-ui-snapshot.md](344-android-ui-snapshot.md).

| # | Severity | Source | Finding | Resolution | Evidence |
| --- | --- | --- | --- | --- | --- |
| 1 | Blocking | PR review | `companion/android/README.md` and plan 344 claimed the tolerance absorbed glyph noise while any layout, text or colour change still failed. Measured: a one-character edit changed 45 px and passed, a short word insertion 740 px passed, a 1 dp spacing change failed at 28,482 px. | Fixed in both docs and in the test's tolerance comment. They now say the gate catches layout-scale changes with an order of magnitude to spare and text changes only above roughly a dozen characters, and they present the budget as insurance for an unproven runner rather than a measured requirement. Plan 344 gained a `What the gate detects` table. | Five probes on the committed baseline: 12 px (appended period) and 654 px (appended short word) pass, 1042 px (`furble` to `Furble`), 1529 px (five characters inserted mid-line) and 27,667 px (1 dp more list spacing) fail. The boundary is glyph-dependent, so a single substitution can pass or fail. |
| 2 | Non-blocking | PR review | Nothing asserted a known node, so an asynchronous repository change reached the comparison as an unexplained pixel count. | Fixed. `CompanionScreenshotTest` asserts the top bar title and the session state line before the capture. | A run with the second assertion pointed at an absent string fails with `The component with Text + InputText + EditableText contains '...' (ignoreCase: false) is not displayed!` instead of a pixel count. |
| 3 | Non-blocking | PR review | The test set the JVM default locale and never restored it. | Fixed. `@Before` saves `Locale.getDefault()` and `@After` restores it. | `./gradlew test --rerun-tasks`: the four JVM classes keep their own locales and all 29 tests pass. |
| 4 | Non-blocking | PR review | `docs/android-dependency-lock.md` said `app-debug.apk` declares one extra activity, but did not say the activity is exported, and read as if the smoke job were untouched. | Fixed. The doc now says the smoke APK gains one exported filterless activity and that the release manifest and the launcher entry are unchanged, so the smoke job still launches `MainActivity`. Plan 344 says the same. | `unzip -p ui-test-manifest-1.12.0.aar AndroidManifest.xml` shows `androidx.activity.ComponentActivity` with `android:exported="true"` and no intent filter. |
| 5 | Non-blocking | PR review | `tools/android-dependency-lock.json` recorded `2026.08.00 (Compose BOM)`, a prose annotation, in place of the resolved version. | Fixed. Both Compose UI test artifacts are recorded as `1.12.0`, the version the BOM pins, and the docs and plan state the same. | `./gradlew :app:dependencyInsight --configuration debugRuntimeClasspath --dependency ui-test-manifest` and the same query for `ui-test-junit4` on `debugUnitTestRuntimeClasspath` both resolve `1.12.0`. |
| 6 | Non-blocking | PR review | Update mode could reuse a cached or up-to-date result, so the baseline write could be skipped. | Fixed both ways. `-PupdateScreenshots` sets `outputs.upToDateWhen { false }` and `outputs.cacheIf { false }` on every test task, and the test writes `companion-main.png.tmp` and moves it over the baseline. | Two consecutive `-PupdateScreenshots` runs execute `:app:testDebugUnitTest` instead of reporting it up to date, also with `--build-cache`, and both wrote sha256 `2a5a82fb...08c0d`. |
| 7 | Non-blocking | PR review | Plan 344 cited plan 121 for the simulator screenshots. | Fixed. It cites plans 76 and 85. | [implemented/76-ui-polish.md](implemented/76-ui-polish.md) (the themes x boards x pages screenshot sweep) and [implemented/85-sim-e2e.md](implemented/85-sim-e2e.md) (the ui-screenshots job). |
| 8 | Non-blocking | PR review | The first-run Robolectric platform jar download was not recorded. | Fixed. "Still open" now names `android-all-instrumented-15-robolectric-14663667-2-i7`, about 197 MB, its `~/.m2/repository/org/robolectric` location and the cache step that would remove it. | `du -sh ~/.m2/repository/org/robolectric/android-all-instrumented/15-robolectric-14663667-2-i7/*.jar` reports 197M. |
